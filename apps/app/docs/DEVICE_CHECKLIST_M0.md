## B. dev-client 단계 — **M0 게이트 본체**

플랜 탭 → "하프톤 스파이크 열기".

원본 비교 대상은 PWA 가 만들던 티켓이다. 나란히 놓고 본다.

| #   | 항목                | 기대                                                   | 판정 |
| --- | ------------------- | ------------------------------------------------------ | ---- |
| B1  | 화면이 뜬다         | "Skia 를 못 불러왔다" 가 아니어야 한다                 |      |
| B2  | **램프 위쪽**       | 구멍 없는 솔리드 로즈. 점이 하나도 없어야 한다         |      |
| B3  | **첫 점 등장 위치** | 램프 높이의 약 44% 지점부터 점이 보이기 시작           |      |
| B4  | **점 성장**         | 아래로 갈수록 점이 굵어진다. 밝기만 흐려지는 게 아니다 |      |
| B5  | **점이 안 붙는다**  | 맨 아래에서도 점끼리 이어져 격자가 되면 안 된다        |      |
| B6  | **점 색**           | 점은 종이색(크림)이다. 흰색이거나 회색이면 틀렸다      |      |
| B7  | 모아레              | 기울여 봐도 무지개 간섭무늬가 생기지 않는다            |      |
| B8  | 숫자 하프톤         | 망점이 글자 안쪽에만 있고 바깥으로 새지 않는다         |      |
| B9  | **그레인 존재**     | 종이 면이 완전 평면이 아니라 미세한 입자가 있다        |      |
| B10 | 그레인 세기         | 왼쪽(0.14)이 오른쪽(0.16)보다 아주 조금 옅다           |      |
| B11 | 그레인 타일 이음새  | 반복 경계선이 보이지 않는다                            |      |
| B12 | **펀치 구멍 모양**  | 좌우가 평평하게 잘린 타원이다. 완전한 원이면 틀렸다    |      |
| B13 | 펀치 간격           | 구멍 사이 간격이 균일하다                              |      |
| B14 | 펀치 색             | 라이트에서 크림, 다크에서 어두운 배경색으로 바뀐다     |      |
| B15 | 스크롤 성능         | 스파이크 화면을 위아래로 훑을 때 끊김이 없다           |      |

### 실패 시 폴백 사다리

1. **그레인만 실패**(`MakeFractalNoise` 가 다르게 나오거나 느림)
   → 그레인 PNG 타일을 사전 래스터화해 번들. 계획 §3.3 이 지정한 1차 폴백.
2. **하프톤 점 분포가 다름**
   → 톤 스톱별 사전 래스터 타일. 램프를 이미지 4장으로 나눠 굽는다.
3. **둘 다 실패**
   → 재구축 전제 재검토. Skia 로 티켓을 그린다는 것이 계획의 D3·D4 를 떠받치고 있으므로
   여기서 무너지면 렌더러 전략 전체를 다시 고른다.

## C. 알려진 비판정 항목

판정하지 **않는다**. 지금 다르게 보이는 것이 정상이다.

- **숫자 글리프 모양** — repo 에 `@font-face` 가 없어 오늘의 화면도 시스템 폴백이다.
  번들 서브셋(`ArchivoBlack`) 도입은 M3 의 별도 사용자 게이트(before/after 승인)다.
- **탭 아이콘** — M0 은 순수 View 도형 자리표시. Skia path 이식은 M2.
- **레이아웃·간격 전반** — 스파이크는 기법 검증용이고 실제 화면은 M2·M3 에서 만든다.
